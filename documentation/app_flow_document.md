# VibeCode App Flow Document

## Onboarding and Sign-In/Sign-Up
When a new user lands on the VibeCode application URL, they first see a welcoming landing page that highlights the Idea Generator and PRD Generator features. Below the introduction, the user can choose to explore the app without logging in or proceed to sign up for an account. If they opt to create an account, they click a “Sign Up” button that opens Clerk’s registration modal. In this modal, the user can enter an email address and password or select a social login option such as Google. Clerk guides the user through email verification if needed. Once the user confirms their email, they are redirected into the application as an authenticated user. Returning users click the “Sign In” button on the landing page, which opens Clerk’s login modal. Here they enter their credentials or choose the same social login provider they used at registration. Clerk manages session cookies so the user remains signed in until they explicitly sign out. If the user forgets their password, the login modal provides a “Forgot Password” link. Clicking it prompts the user to enter their email, after which Clerk sends a password reset link. Following that link allows the user to set a new password and return automatically to the app once the process completes. Signing out is as simple as clicking a profile icon and choosing “Sign Out,” at which point Clerk clears the session and returns the user to the landing page. Throughout these steps, the user interface clearly indicates whether the user is authenticated or using the app in guest mode. 

## Main Dashboard or Home Page
After signing in, the user arrives at the main dashboard, which features a clean header with the VibeCode logo on the left and a profile icon on the right. Below the header, a horizontal navigation bar presents two main options: Idea Generator and PRD Generator. In guest mode, selecting either option routes the user directly to the corresponding page but without saving history. In authenticated mode, the user sees an additional sidebar on the left that lists their past sessions and allows them to reload previous conversations. The central area of the dashboard displays a welcome message that invites the user to start a new session by choosing one of the generator tabs. The bottom of the sidebar houses a link to Settings. From this dashboard, clicking “Idea Generator” or “PRD Generator” smoothly transitions the user to the generator interface. The header remains sticky, and the profile icon opens a dropdown menu for signing out or jumping to account settings at any time. This consistent layout ensures that users always know how to navigate between generators, return to the home dashboard, or access their account tools. 

## Detailed Feature Flows and Page Transitions
When the user clicks on Idea Generator, the main content area replaces the welcome screen with a chat-style interface. The top of this area displays a prompt input field pre-populated with a template power prompt. Next to the prompt field is an agent selector dropdown that lists options such as “Claude Sonnet 4.5” or “Gemini 2.5 Flash.” The user can edit the prompt freely before hitting the “Send” button. On click, the prompt and selected agent are sent via a TanStack React Query useMutation hook to the `/api/ai` endpoint. The page immediately shows a loading indicator, then streams the AI response into the chat area using a ReadableStream. Each streamed chunk appears as part of the assistant’s message bubble. Once the response is complete, the user sees “Download,” “Reload,” and “Edit” icon buttons. Clicking “Download” triggers a markdown or PDF export of the latest session. “Reload” re-sends the original prompt through the same mutation logic and re-renders the conversation. “Edit” brings the user back to the prompt input with the previous content, allowing quick revisions. The PRD Generator page follows the exact same flow, with a specialized template that guides the AI to produce a product requirements document. Navigation back to the main dashboard happens via a sidebar link or by clicking the app logo, seamlessly preserving the user’s state. In authenticated sessions, every conversation is saved to Firebase Firestore behind the scenes, and newly saved sessions appear in the sidebar in real time. 

## Settings and Account Management
The Settings page is accessible from the sidebar or profile dropdown and loads a simple form where the user can update their name, email, and notification preferences. All fields validate input live, and updating triggers Clerk API calls to sync profile data. For users on paid plans, a Billing section appears beneath the profile settings, showing current subscription details, next billing date, and a button to change or cancel the plan. Any changes here call the payment provider API behind the scenes and then update the user’s subscription status in the dashboard sidebar. After saving changes, a confirmation banner appears at the top, and the user can click “Back to Dashboard” to return. The app retains their new preferences immediately, and if they adjust notification toggles, the AI-generated session alerts respect the updated settings. This settings flow makes it clear how to manage personal data and billing without ever leaving the core app structure. 

## Error States and Alternate Paths
If the user enters an invalid prompt or the API returns a validation error, the chat input area highlights the field in red and displays a concise error message below it. For network errors, the interface shows an unobtrusive banner at the top reading “Network Issue. Trying again...,” and the system automatically retries the request up to two times before displaying a “Retry” button. In the event the AI provider rejects a request or times out, the user sees a bubble stating “AI service unavailable. Please try later.” Clicking “Reload” or “Retry” returns the user to the ready state. If the user attempts to access a protected page while not signed in, Clerk intercepts the request and presents the login modal. After successful authentication, the user is redirected back to their intended page. Should the user’s session expire, any API call returns a 401 status, and the app prompts them to sign in again via a modal. These error and alternate flows ensure the user never gets stuck and always has a clear path back to productive work. 

## Conclusion and Overall App Journey
From the landing page to generating ideas and PRDs, VibeCode guides the user through a straightforward, chat-based workflow. Users can explore the generators in guest mode or opt to sign up for a richer experience that remembers their history and unlocks downloads. The main dashboard provides simple navigation between generators and settings while maintaining a consistent header and sidebar. Core features like prompt editing, AI streaming, download export, and conversation reloading are all orchestrated from the generator pages. Settings and billing management are available without disrupting the creative flow. Throughout, clear error handling and redirects keep users in control and on track. In a typical session, a user signs in once, navigates to an idea or PRD generator, crafts a prompt, receives an AI response within seconds, and then reviews or downloads the output before moving on. This fluid journey ensures that from the first click to everyday usage, VibeCode delivers an accessible, responsive, and intuitive AI-powered workflow experience.
